# Git/GitHub & Pydantic 정리

## 1. GitHub 레포 Push / Pull 사용법

### 기본 흐름
```bash
# 1. 레포 클론 (처음 한 번만)
git clone https://github.com/사용자명/레포이름.git
cd 레포이름

# 2. 변경사항 확인
git status

# 3. 변경 파일 스테이징
git add .              # 전체 추가
git add 파일명          # 특정 파일만 추가

# 4. 커밋
git commit -m "커밋 메시지"

# 5. 원격 저장소로 push
git push origin main    # 브랜치명은 main 또는 master

# 6. 원격 저장소 변경사항 받아오기
git pull origin main
```

### 자주 쓰는 명령어
| 명령어 | 설명 |
|---|---|
| `git init` | 현재 폴더를 git 레포로 초기화 |
| `git remote add origin <URL>` | 원격 저장소 연결 |
| `git remote -v` | 연결된 원격 저장소 확인 |
| `git log` | 커밋 히스토리 확인 |
| `git branch` | 브랜치 목록 확인 |
| `git checkout -b 브랜치명` | 새 브랜치 생성 및 이동 |

### 최초 연결 시 (로컬 폴더 → 새 GitHub 레포)
```bash
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/사용자명/레포이름.git
git push -u origin main
```

## 2. 레포 연결 끊기 (로컬 + GitHub 완전 삭제)

### 2-1. 로컬 폴더에서 git 연결 끊기
`.git` 폴더는 숨김 파일이라 탐색기/Finder에서 "숨김 항목 보기"를 켜야 보입니다.

**Windows (탐색기)**
- 보기 → 숨긴 항목 체크 → `.git` 폴더 삭제

**Mac (Finder)**
- `Cmd + Shift + .` 로 숨김 파일 표시 → `.git` 폴더 삭제

**터미널로 삭제 (더 간단)**
```bash
# 레포 폴더로 이동 후
rm -rf .git          # Mac / Linux
rmdir /s /q .git      # Windows (cmd)
Remove-Item -Recurse -Force .git   # Windows (PowerShell)
```
> `.git` 폴더만 지우면 폴더 자체는 남고, git 이력/원격 연결 정보만 사라집니다 (일반 폴더가 됨).

### 2-2. GitHub에서 원격 레포 삭제
1. GitHub 접속 → 삭제할 레포 페이지 이동
2. 상단 탭에서 **Settings** 클릭
3. 맨 아래로 스크롤 → **Danger Zone** 섹션
4. **Delete this repository** 클릭
5. 확인 문구(레포 전체 경로, 예: `사용자명/레포이름`)를 정확히 입력
6. **I understand the consequences, delete this repository** 클릭 → 완료

⚠️ 삭제는 되돌릴 수 없으니, 필요하면 미리 zip 백업이나 다른 계정으로 fork 해두는 것을 추천합니다.

## 3. Pydantic 개념 정리

### Pydantic이란?
Python 타입 힌트를 기반으로 **데이터 검증(validation)**과 **설정 관리**를 해주는 라이브러리입니다. 클실래스에 타입을 선언해두면, 제 데이터가 들어올 때 그 타입에 맞는지 자동으로 검사하고 변환해줍니다.

### 왜 쓰는가?
- **자동 타입 검증**: 잘못된 타입의 데이터가 들어오면 명확한 에러를 발생시켜 버그를 조기에 발견
- **자동 형변환**: `"3"` 같은 문자열도 `int` 필드면 자동으로 `3`으로 변환 시도
- **코드 가독성/문서화**: 데이터 구조가 클래스 형태로 명시되어 있어 스키마 파악이 쉬움
- **FastAPI 등과의 통합**: FastAPI의 요청/응답 스키마 검증에 기본으로 사용됨
- **JSON ↔ 객체 변환**: API 응답이나 설정 파일(JSON)을 파이썬 객체로 쉽게 변환
- **에러 메시지가 친절함**: 어떤 필드가 왜 잘못됐는지 상세히 알려줌

간단히 말하면, "이 데이터는 이런 모양이어야 한다"를 코드로 선언하고, Pydantic이 그 약속이 지켜지는지 자동으로 검사해주는 도구입니다.

## 5. 공식 문서 기반 예시 코드

아래 예시들은 Pydantic 공식 문서(https://docs.pydantic.dev)에서 다루는 대표 패턴을 참고해 작성했습니다. 주제별로 파일을 나눠서 정리했습니다.

### `pydantic1.py` — 기본: 데이터 검증과 타입 변환
- 기본 모델 정의 및 자동 타입 변환 — `BaseModel`로 필드 타입을 선언하고, 문자열 숫자가 자동으로 int로 변환되는 예시
- 유효성 검사 실패 처리 — `ValidationError`를 잡아서 어떤 필드가 왜 실패했는지 확인하는 예시

### `pydantic2.py` — 실전: 기본값, Optional, 중첩 모델
- 기본값(default)과 Optional 필드 — 값을 생략해도 기본값이 채워지고, `Optional[str] = None`처럼 없어도 되는 필드를 다루는 예시
- 중첩 모델(nested model) + 커스텀 검증 — 모델 안에 다른 모델(`Address`)을 필드로 중첩하고, `field_validator`로 커스텀 검증 규칙(나이 범위 등)을 추가하는 예시

> **개념: 기본값 vs Optional은 다르다**
> - `age: int = 20` → 필드를 **생략**할 수 있고, 생략하면 20이 들어감 (필드는 필수가 아님, 타입은 여전히 `int`만 허용)
> - `nickname: Optional[str] = None` → 값으로 **`None`이 들어와도** 허용한다는 의미 (`str` 또는 `None`)
> - 즉 "생략 가능"과 "None 허용"은 별개 개념이라, 실전에서는 상황에 맞게 `기본값만`, `Optional만`, 또는 `Optional + 기본값`(`Optional[str] = None`) 조합을 골라 써야 함
>
> **개념: 중첩 모델을 쓰는 이유**
> 실무 데이터는 대부분 계층 구조(회원 안에 주소, 주문 안에 상품 목록 등)를 가짐. 하나의 모델에 모든 필드를 평평하게 넣는 대신 `Address`처럼 의미 단위로 모델을 쪼개 중첩하면 ① 재사용이 쉽고 ② dict를 그대로 넘겨도 Pydantic이 알아서 하위 모델로 변환/검증해줘 코드가 간결해짐.

### `pydantic3.py` — 실전: API 요청 → 검증 → 데이터 변환
- 요청 모델(`SignupRequest`)로 들어온 데이터를 검증(이메일 형식, 커스텀 username 규칙 포함)
- 검증에 성공하면 내부용 모델(`UserRecord`)로 변환(이메일 소문자 정규화, 생년 → 나이 계산 등)해 응답/DB 저장에 사용하는 흐름 예시
- 검증 실패 시 `ValidationError`의 오류 목록을 클라이언트 응답 형태로 가공하는 예시
- `EmailStr` 타입을 쓰므로 `pip install pydantic email-validator` 필요

> **개념: 요청(Request) 모델과 내부(Internal) 모델을 왜 분리하는가**
> 실제 API 서버(FastAPI 등)에서는 보통 아래 3단계 흐름을 따름:
> 1. **요청 모델**로 클라이언트가 보낸 원본 데이터의 형태/타입을 검증 (예: `SignupRequest`)
> 2. 검증을 통과한 데이터를 서비스 로직에서 쓰기 좋은 **내부 모델**로 가공/변환 (예: `UserRecord` — 이메일 정규화, 생년→나이 계산처럼 원본에는 없던 값을 파생)
> 3. 내부 모델을 다시 **응답/저장용 형태**(JSON, DB row 등)로 내보냄
>
> 이렇게 나누면 "클라이언트가 보내는 값"과 "서버 내부/DB에서 쓰는 값"이 달라져도(필드명, 단위, 파생값 등) 서로 영향을 주지 않고, 검증 실패는 요청 단계에서 조기에 걸러낼 수 있음.

각 파일은 `python 파일명.py`로 바로 실행할 수 있습니다.

## 6. NumPy 개념 정리

### NumPy란?
파이썬에서 **다차원 배열(ndarray)** 을 다루고, 배열 단위로 빠르게 수치 연산을 할 수 있게 해주는 라이브러리입니다. 데이터 분석, 머신러닝, 과학 계산의 기반이 되며 Pandas·Matplotlib 같은 라이브러리도 내부적으로 NumPy 배열을 사용합니다.

### 왜 쓰는가?
- **속도**: 파이썬 리스트로 반복문을 돌리는 것보다 NumPy 배열 연산이 훨씬 빠름 (내부적으로 C로 구현됨)
- **벡터화 연산**: `for`문 없이 배열 전체에 연산을 한 번에 적용 가능 (`a + b`, `a * 2` 등)
- **다차원 데이터 표현**: 표(2차원), 이미지(3차원) 등 다양한 차원의 데이터를 자연스럽게 표현
- **풍부한 통계/수학 함수**: 평균, 표준편차, 정렬, 조건 필터링 등을 내장 함수로 바로 사용 가능
- **생태계 표준**: Pandas, Matplotlib, scikit-learn 등 대부분의 데이터 관련 라이브러리가 NumPy 배열을 기본 입출력으로 사용

### 파이썬 리스트와의 차이
- 리스트는 서로 다른 타입을 섞어 담을 수 있지만, NumPy 배열(`ndarray`)은 **하나의 타입(dtype)** 으로 통일되어 있어 메모리 효율과 연산 속도가 좋음
- 리스트끼리 `+`를 하면 이어 붙이기(concat)가 되지만, NumPy 배열끼리 `+`는 **원소별 덧셈**이 됨 (완전히 다른 동작이므로 주의)

## 8. NumPy 예시 코드

Pydantic 예시와 같은 방식으로, 주제별로 파일을 나눠서 정리했습니다.

### `numpy1.py` — 기본: 배열 생성과 기본 연산
- 배열 생성과 속성 확인 — `np.array`, `np.zeros`, `np.ones`, `np.arange`, `np.linspace`로 배열을 만들고 `shape`/`ndim`/`size`/`dtype`을 확인하는 예시
- 벡터화 연산과 브로드캐스팅 — 반복문 없이 배열끼리, 배열과 스칼라끼리 연산하는 예시
- 인덱싱과 슬라이싱 — 1차원/2차원 배열에서 원하는 원소·행·열·부분 배열을 꺼내는 예시

> **개념: 브로드캐스팅(broadcasting)**
> 크기가 다른 배열끼리 연산할 때, NumPy가 작은 쪽을 자동으로 "확장"해서 크기를 맞춰주는 규칙. 예를 들어 `(2, 3)` 행렬에 `(3,)` 벡터를 더하면, 벡터가 각 행에 반복 적용된 것처럼 계산됨. 명시적으로 반복문이나 `tile`을 쓰지 않아도 되어 코드가 간결해짐.

### `numpy2.py` — 실전: 배열 조작과 통계/집계 함수
- 배열 형태 변경 — `reshape`, `transpose(.T)`, `concatenate`로 배열의 모양을 바꾸거나 이어 붙이는 예시
- axis 개념과 통계 함수 — `mean`/`sum`/`max`/`std`에 `axis`를 지정해 행 방향/열 방향으로 집계하는 예시
- 정렬과 조건 필터링 — `sort`/`argsort`, 불리언 인덱싱(`arr[조건]`), `np.where`로 조건에 따라 값을 뽑거나 치환하는 예시

> **개념: axis는 "어느 방향을 없앨지"를 지정하는 것**
> `axis=0`은 **행 방향(세로, 아래로)** 으로 계산해서 각 열의 결과를 남기고, `axis=1`은 **열 방향(가로)** 으로 계산해서 각 행의 결과를 남김. "axis=0이면 행끼리, axis=1이면 열끼리 계산된다"고 헷갈리기 쉬운데, 실제로는 **그 axis 방향을 따라 값을 합쳐서 없앤다**고 이해하면 헷갈리지 않음 (`axis=0` 지정 → 행 개수만큼 있던 축이 사라지고 열 개수만큼 결과가 남음).

### `numpy3.py` — 응용: 데이터 전처리 파이프라인 (원본 → 정제 → 정규화 → 요약)
- 결측치(NaN)가 섞인 원본 점수 데이터를 `np.isnan`으로 확인하고 제거해 정제하는 예시
- 정제된 데이터를 평균 0·표준편차 1로 만드는 정규화(z-score standardization) 예시
- 최종적으로 count/mean/std/min/max/median을 담은 요약 통계 dict를 만드는 예시

> **개념: 데이터 전처리 파이프라인 (원본 → 정제 → 변환 → 요약)**
> 실제 데이터 분석에서는 원본 데이터를 그대로 계산에 쓰지 않고, `pydantic3.py`의 "요청 검증 → 내부 변환" 흐름처럼 ① 결측치/이상치를 정제 → ② 분석하기 좋은 형태로 변환(정규화 등) → ③ 최종 지표로 요약하는 단계를 거침. 이렇게 단계를 나누면 어느 단계에서 데이터가 잘못됐는지 추적하기 쉽고, 각 단계를 재사용하거나 테스트하기도 쉬움.

각 파일은 `python 파일명.py`로 바로 실행할 수 있습니다.

## 9. 클래스(Class) 개념 정리

### 클래스란?
데이터(속성)와 그 데이터를 다루는 동작(메서드)을 하나로 묶은 설계도입니다. 클래스로 찍어낸 실제 결과물을 **인스턴스(객체)** 라고 부르며, 같은 클래스에서 만든 인스턴스들은 서로 독립적인 데이터를 가집니다.

### 왜 쓰는가?
- **데이터 + 동작을 한 곳에 묶음**: 관련 있는 값과 함수를 흩어놓지 않고 하나의 단위(클래스)로 관리
- **재사용성**: 같은 구조가 필요할 때마다 클래스에서 인스턴스만 새로 찍어내면 됨
- **상속을 통한 확장**: 기존 클래스의 기능을 재사용하면서 필요한 부분만 추가/재정의 가능
- **다형성**: 같은 이름의 메서드를 호출해도 객체 타입에 따라 다르게 동작 → 호출하는 쪽 코드는 타입을 몰라도 됨
- **캡슐화**: 내부 데이터를 직접 건드리지 못하게 막고, 정해진 메서드/property로만 접근하게 해 안전하게 관리

### 자주 헷갈리는 용어
- **클래스(Class)**: 설계도. `class Dog:` 처럼 정의
- **인스턴스(Instance/Object)**: 클래스로 실제로 만든 결과물. `Dog("바둑이", 3)`
- **속성(Attribute)**: 인스턴스가 가지는 데이터. `self.name`
- **메서드(Method)**: 클래스 안에 정의된 함수. 첫 인자로 보통 `self`(인스턴스 자신)를 받음

## 10. 클래스 예시 코드

Pydantic/NumPy 예시와 같은 방식으로, 주제별로 파일을 나눠서 정리했습니다.

### `class1.py` — 기본: 클래스 정의와 인스턴스
- 클래스 정의와 인스턴스 생성 — `__init__`으로 속성을 초기화하고, 인스턴스마다 독립적인 데이터를 갖는 예시
- 클래스 변수 vs 인스턴스 변수 — 모든 인스턴스가 공유하는 값과, 인스턴스마다 따로 갖는 값의 차이를 확인하는 예시
- 인스턴스 메서드 vs classmethod vs staticmethod — 세 가지 메서드 종류의 용도 차이를 비교하는 예시

> **개념: self는 왜 필요한가**
> 인스턴스 메서드의 첫 번째 매개변수 `self`는 "이 메서드를 호출한 인스턴스 자기 자신"을 가리킴. `d1.bark()`처럼 호출하면 파이썬이 자동으로 `Dog.bark(d1)`로 바꿔 호출해주는 것과 같아서, 메서드 안에서 `self.name`으로 그 인스턴스만의 속성에 접근할 수 있음.

### `class2.py` — 실전: 상속, 다형성, 캡슐화
- 상속과 메서드 오버라이딩(다형성) — 부모 클래스를 상속받아 메서드를 재정의하고, 같은 메서드 호출이 타입마다 다르게 동작하는 예시
- `super()`로 부모 초기화 재사용 — 자식 클래스에서 부모의 `__init__`을 재사용해 중복을 줄이는 예시
- 캡슐화 + property — `__balance`처럼 이름 앞에 `__`를 붙여 외부에서 직접 접근하지 못하게 막고, `@property`로 안전하게 값을 노출/검증하는 예시

> **개념: 캡슐화를 왜 하는가**
> 속성을 아무 데서나 직접 바꿀 수 있게 열어두면(`account.balance = -9999999`처럼) 데이터가 잘못된 상태가 될 위험이 있음. `__balance`처럼 이름을 감추고 `deposit()`/`withdraw()` 같은 메서드나 `@property`를 통해서만 값을 바꾸게 하면, 그 메서드 안에서 유효성 검사를 강제할 수 있어 객체가 항상 올바른 상태를 유지함.

### `class3.py` — 응용: 특수 메서드(dunder)를 활용한 실전 객체 설계
- `__repr__`/`__eq__`/`__lt__` 같은 특수 메서드(dunder)를 정의해 `print()`, `==`, 정렬(`sorted`)이 자연스럽게 동작하게 만드는 예시
- 재고 관리 파이프라인 — 원본 dict 목록을 `Product` 객체로 변환 → 가격순 정렬/재고 필터링 → 총 재고 가치 등 요약 통계를 만드는 흐름 예시

> **개념: 특수 메서드(dunder, magic method)**
> `__init__`, `__repr__`, `__eq__`, `__lt__`처럼 앞뒤로 `__`가 붙은 메서드들은 파이썬이 내장 문법(`print()`, `==`, `<`, `sorted()` 등)을 처리할 때 자동으로 호출하는 "약속된 이름의 메서드"임. 이걸 직접 정의해두면 내가 만든 클래스도 파이썬 기본 타입처럼 자연스럽게 비교·정렬·출력할 수 있게 됨.
>
> **개념: 원본 데이터 → 객체 변환 → 처리 → 요약 패턴**
> `pydantic3.py`(요청 → 검증 → 변환), `numpy3.py`(원본 → 정제 → 정규화 → 요약)와 같은 맥락으로, `class3.py`도 raw dict 목록을 그대로 다루지 않고 먼저 의미 있는 객체(`Product`)로 변환한 뒤 정렬·필터링·요약을 수행함. 데이터를 다루는 실무 코드에서 자주 반복되는 패턴이므로 함께 기억해두면 좋음.

각 파일은 `python 파일명.py`로 바로 실행할 수 있습니다.
